# 仓库并行调查

先界定要回答的问题和目标工作树，快速看目录及入口，再按问题划分互补方向。若查 A 才知道如何查 B，先查 A；一个定义就能回答的，直接读取并标为单点调查。并行有价值且宿主提供并允许本次委派时，实际启动 subagent，使独立方向能同时推进；主 agent 也可承担一个方向。数量取决于有用方向和宿主能力，不为凑数重复搜索。技能被隐式选中不会授予新的委派权限。

给每个 subagent 明确：目标仓库与范围、它负责的独立问题、适用规则、只读边界、返回什么。不要假设它继承了对话。主、子 agent 在**本次调查**中都只检查现有源码、配置、测试文本、文档和只读历史；不执行项目代码，不装依赖、启动服务、构建、更新索引或快照，不写报告文件。证据和交接留在对话中。这一边界不限制外层任务另行授权的后续实施。

让每个子任务返回「结论 → 文件路径及行号或符号 → 此处直接说明了什么」，附上冲突、未确认事项和未查范围。主 agent 等待结果，亲自重读支撑最终答案的关键位置；有矛盾时检查调用链、配置生效条件和版本，不能消解就保留分歧，不靠多数票定论。

答复先回答问题，再区分直接核实的事实、据此作出的推断和仍缺失的证据。准确说明采用了子代理并行、部分委派还是串行。需要并行而委派不可用、不获准或执行失败时，说明**没有完成所需的并行调查**及具体原因；可在原边界内串行查证其余部分。并发 shell 命令不等于 subagent。
