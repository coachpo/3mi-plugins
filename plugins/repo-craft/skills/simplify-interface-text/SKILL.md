# 清理界面文案

删除不改变读者行动、也不增加读者所知的界面文字；保留保护性文字和唯一信息。必要但冗长的文字加以缩写，保留它告诉读者的全部内容。没有发现值得改动的地方也是有效结论。

每次调用都从审查开始：一次走查，只给出发现，不修改源码、文案、配置或既有记录；例外见下文的测试记录。给出发现清单，就是否清理询问一次，确认后把范围内的改动一直做到验证完成。针对整份清单询问，不逐条询问；用户可以排除其中的发现。

两类请求会改变这一流程。只要求审查的请求，在给出发现清单后结束，不询问。明说直接改文字、不用询问的请求，或给出、引用了一份用户已接受的清单的请求，跳过询问。与[精简仓库](../simplify-repo/SKILL.md)不同，这项工作有意改变可见输出。它仍然不改命令、金额、已存储的事实或服务端契约。

## 确定规则、范围与授权

项目的贡献指南或其他权威文档写有已采纳的界面文案规则时，采用项目的规则。否则采用[贡献指南模板](../maintain-project-docs/references/CONTRIBUTING.template.md)“界面文案”一节的原则，并说明用的是它。不把记录项目政策当作审查的副产品。

查明范围内的界面、角色、语言和环境，以及在每个环境中获得了什么授权。为复现某个页面状态，创建带标记的测试记录并在流程中推进它们。在非生产环境，请求本身即覆盖这一步；在生产环境需要用户针对该环境的指示，只要求审查的请求不在生产环境这样做。不动其他记录；除非用户要求，不删除测试记录。授权不延伸到另一个环境。

登录、验证或其他阻碍使某个环境无法进入时，报告这一情况；只有获得授权才改用另一个可进入的环境。不猜测地址、凭据或页面内容。

## 判断渲染出的屏幕

重复和噪音存在于屏幕上，不存在于字符串表里。两个键的措辞相近不算发现，除非有人会同时看到它们；而单独一个键也可能是发现，只要它出现在已经说了同一件事的标题、徽标或控件旁边。

按角色和状态走查每个界面。覆盖会改变显示内容的状态：空与有数据、正常与异常、进行中与已完成、只有一个可选项与有多个、某项能力已启用与未启用。尽可能把页面当作文本来读；位置有影响时再看渲染效果。

到不了的状态从源码读取，并把这些发现标为“读自源码”而不是“实际观察”。读源码是对走查的补充，不代替走查。

对每一段文字，判断它是源码还是实例数据，如保存的设置、受管理的内容或种子记录。改仓库修不了实例数据。把这类发现单独列给内容的所有者。

## 记录发现

给每条发现一个稳定的标识，使清理结果可以对照它报告，并记录：

- 所在屏幕，以及这段文字出现的条件。
- 文字原文。
- 它违反了哪条规则，以及读者为什么在那里不需要它。
- 拟议的改动：删除、缩写、移动或按条件显示；缩写的要给出替换文本。
- 源码位置，或说明它是实例数据。
- 是实际观察到的，还是读自源码。

一个事实在多处重复时只报一条发现，并指明由哪一处保留它。看似冗余但必须保留的文字连同理由一并记录，以免之后的清理把它删掉。不凑数：一条发现必须通过规则本身的检验，即删掉它会不会误导读者或丢失事实。

## 清理

按用户已接受的清单工作时，新发现的问题只报告，不加进清单。

- 缩写后的文字保留原文的每一个事实、条件、数值、单位、专有名词和要求的动作，并使用项目既定的术语。无法在不丢失其中任何一项的前提下缩写时，保持原样并报告原因。
- 所有支持的语言一起改。每种语言的缩写文本都从含义出发来写，不从另一种语言的结果翻译。某个键不再被引用时，按项目的兼容政策把它从每种语言及其类型中删除。
- 文案改动包含渲染它的条件。“正常状态下不显示这段文字”要用屏幕已有的事实实现，范围以发现所需为限。某条发现需要新的业务逻辑或契约变更时，保持原样并报告原因。
- 保留明确的确认、别处没有显示的值，以及承担功能的文字。删除含有值（如修订号、标识符或金额）的文字之前，检查谁依赖它：读者、支持流程，还是把它当作状态证据的测试。
- 更新断言或描述了被改文字的测试和文档。不添加只为证明某句话已被删除的测试。
- 实例数据保持不变，除非在该环境中编辑它已获授权。

## 验证

运行项目针对受影响代码的检查，包括断言了被改屏幕的界面测试。界面测试失败时，先与改动前的基线比较，再判断失败是否由清理造成。原本就已过时的断言予以报告，不为了通过而改写。

在可行的情况下，查看受影响状态下被改动的屏幕。说明哪些屏幕实际查看过、哪些只由测试覆盖、哪些测试套件更新了但没有运行。之后的修改会使受影响的结果失效。

## 报告结果

对每个发现标识，说明它已改动、部分改动（以及结果与提议有何不同），还是未改动及其原因。给出每段被改文字的改前和改后文本。与用户已接受的清单的每一处偏离都要指出。

说明实际运行的验证及其结果、尚未验证的范围、留给所有者处理的实例数据发现，以及留下的测试记录或本地状态。

## 与其他技能配合

- 用户希望把界面文案规则记入项目文档时，使用[项目文档维护](../maintain-project-docs/SKILL.md)。
- 需要保全行为的清理时，建议使用[精简仓库](../simplify-repo/SKILL.md)；它需要用户主动调用。
- 独立搜索文案来源有用时，使用[仓库并行调查](../investigate-repo/SKILL.md)。
