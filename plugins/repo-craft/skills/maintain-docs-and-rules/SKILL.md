# 初始化与维护项目文档和工作规则

审查只读，只报告事实、缺口和拟议的改动；请求初始化、维护或更新时才写入。只给出技能名、没有说是否写入时先按审查处理。

默认两部分都做，先文档后规则，使规则链接到的文档已经存在。请求只提文档或只提规则时，只做那一部分；仅要求改某篇文档或某个 `AGENTS.md` 时限定到那个文件，不借机初始化全仓。多个模块或子树能独立取证时复用[仓库并行调查](../investigate-repo/SKILL.md)；先结束只读调查，再由主 agent 做获准的修改。

## 项目文档

初始化或维护整套文档时，先盘点下列位置、现有文档（包括其他路径、译本和受生成器管理的区域）及有效内容。

| 项目根下的路径 | 内容归属与证据 |
| --- | --- |
| `README.md` | 项目用途、经清单或入口核实的快速开始、实际存在的文档入口 |
| `ARCHITECTURE.md` | 从实现和调用关系确认的模块边界与关键数据流；契约级细节放进专题文档，从这里链接 |
| `CONTRIBUTING.md` | 贡献者共用的设计、实现、验证与提交流程，以及项目确立的产品与业务约束；项目命令和现行约定从配置、测试入口或已确认的规则核实 |
| `CHANGELOG.md` | 可核实的版本历史与用户可感知变化；提交日期不等于发布日期 |
| `docs/adr/` | 有决策依据时记录背景、选择和原因；当前实现本身不能证明当初为何选择它 |
| `docs/operations.md` | 有配置、流程或有效手册支持的部署、监控、排障、回滚与恢复；沿用旧手册而仓库无法核实的内容标注为未核实，可以整节标注 |
| `docs/<专题>.md` | 有证据的契约级细节：调用方、数据或恢复行为所依赖的事实，如端点表、状态机、数据格式、持久化键和时间常数；纯版式和内部实现机制不写。按需建立，不建空占位 |

首次初始化空项目时，`CONTRIBUTING.md` 写入完整模板，其余四个文档建为占位文档，并创建空的 `docs/adr/` 目录（及必要父目录）。占位文档只含下面这一行注释，不加标题或示例：

```markdown
<!-- 空占位文档：尚无有证据的内容。写入内容时删除本行。 -->
```

专题文档不建占位，空目录里不放隐藏文件。Git 不跟踪空目录；仅当用户要求随 Git 保留时，先核实该仓库的占位惯例，不明确就询问，不能自行决定使用 `.gitkeep`。

维护整套文档时，已有项目也补齐缺失的固定位置。除贡献指南的模板规则外，有证据才填写相应内容；没有证据且目标缺失或为零字节，就写成占位文档。固定位置上已有的有效内容不截断、不清空、不为统一格式整篇替换。若目标被不相容的文件类型占用，先报告冲突，不强制覆盖。无历史证据时新建的版本记录保持为占位，不补写 ADR。撰写 ADR 时沿用项目已有的命名和结构；没有时用 `docs/adr/NNNN-<slug>.md`，至少写明背景、决策和原因。决策日期不可核实就不写；依赖外部事实而仓库无法核实的理由保留，并标注为未核实。

内容属于上表归属、却在上表位置之外的旧文档，默认由固定结构取代，不先询问：模块边界和关键数据流归入 `ARCHITECTURE.md`，操作流程归入运维文档，写明了理由的决策归入 ADR，契约级细节归入专题文档；有效内容收进去之后删除原件，并修复指向它的链接。不为压缩篇幅舍弃仍然有效的内容，确实舍弃的在报告中逐项列出并说明原因。以下不算旧文档：`docs/` 下内容属于契约级细节的专题文档、固定位置文档的译本、许可证、由平台或工具按固定路径读取的文件，以及子模块自己的 README。`AGENTS.md` 与 `CONTRIBUTING.md` 按[模板](#模板)一节合并，不整篇取代。用户要求保留的文档留在原处，需要时从固定结构引用。要变更受生成器管理的区域的权威来源，先说明涉及的路径和影响，请用户确认。只审查时只报告拟议的取代和拟舍弃的内容。

从 README 给有实质内容的文档提供入口；已有入口可用就沿用，不为占位文档添加导航，也不因空项目已有贡献模板而填充 README。再次运行时不重复追加同一规则或事实，不改写未变化的文档。专题文档按主题切分，一个主题一篇，文件名沿用项目已有的命名方式，没有时用小写连字符；每篇都从 `ARCHITECTURE.md` 链接，这就算有入口，README 是否逐篇列出不作要求。

指出零散的进度文件（如 `PROGRESS.md`、`NOTES.md`）、遗留的 `.agent-work/` 目录，以及文档中的进度内容。获准迁移时，把仍有效的持久事实移到固定结构中对应的文档，其余列为删除候选；只审查时只报告拟议的迁移。不删除其他任务的工作目录。

## 项目规则

开始前读现有根规则、相关祖先和子目录规则，包括可能遮蔽它们的宿主覆盖文件；区分仓库里存在的文件和本次宿主确实加载的指令。不要修改覆盖文件、用户级配置或指令。

递归查看仓库内有人维护的模块、清单、脚本、CI、生成边界和文档，区分共享流程和局部例外。清单里有命令，不代表当前可用：核对执行目录、引用的脚本和输入是否存在；缺前提时报告缺口，不把它列为可用的验证步骤。不要只检查当前目录或为依赖、构建产物逐目录写指南。

初始化时按需核查以下线索；它们是候选检查项，不是输出提纲。不固定 `AGENTS.md` 的标题、字数或章节。

- 目录结构：哪些路径是修改入口，哪些是生成产物？不必罗列整棵目录树。
- 常用命令：从清单、脚本和 CI 核对构建、本地运行及验证入口，留意工作目录和前置条件。
- 风格工具：从配置和实际调用确认格式化器、lint 工具及其适用范围，不复述工具已执行的每条规则。
- 测试：核对测试入口、用例放置与命名，以及项目实际要求的检查；不推定覆盖率门槛。
- 提交和 PR：核对贡献指南、PR 模板和自动检查；Git 历史可佐证惯例，但个别提交不能确立政策。
- 生产标识：项目有生产部署且有证据时，在根文件按名称列出能识别生产或真实账号的对象：数据库和其他数据存储（名称、实例或保存连接串的变量）、部署目标（账号、项目、服务名）、触发生产部署的分支、生产域名，以及生产或真实账号密钥的变量名或文件名。不写密钥值。每项取自已核实的配置、CI、现有文档或用户说明，未核实的标注出来；不声称清单穷尽。没有生产部署时，写明这是工作假设以及什么证据会推翻它，并列出已知的远程非生产目标。

除模板条款外，只补充会改变 Agent 操作的项目规则。设计、兼容与迁移、测试要求、界面文案、提交与 PR 格式，以及项目确立的产品与业务约束属于贡献指南；需要时链接到项目已有的对应小节，只补充影响当前操作的入口或局部例外。不复制贡献政策，不为去重改动另一份文档，也不为尚不存在的目标造链接。

补充项目规则时，全仓通用的写根文件。只在一个子树与上层有**实质差异**且有证据时，为它写局部规则：构建入口、验证命令或生成文件处理不同，或者有该子树特有、只读父级就会违反的约束。判据是这个问题：“只读父级，执行者会在这里做错什么？”每条局部规则都要能回答它，写成一句指出具体错误的操作规则，细节链接到架构文档或贡献指南；没有具体答案就不新建子文件。约束只在该子树内成立才写进子文件；全仓都成立的写根文件或贡献指南，一两句就能说清的差异也并回根文件。子文件里的一句操作规则不算复制贡献政策，但理由和细节留在它链接的文档里，链接目标也可以是专题文档。实现描述、目录清单和对父级的复述不写进子文件。共用流程不拆成多份；现有子规则没有新差异时不为统一格式而改写。

找不到佐证不等于人工约束失效。现有规则与仓库事实不符或有效性不明时，说明证据并请用户确认，不自行删除。指出 `AGENTS.md` 中混入的任务进度、会话记录和临时 TODO；只在获授权的清理范围内删除。

## 模板

根 `AGENTS.md` 采用[根规则模板](references/AGENTS.template.md)，`CONTRIBUTING.md` 采用[贡献指南模板](references/CONTRIBUTING.template.md)，都按[模板写入与合并](references/template-merge.md)处理：缺失或零字节时全量写入；非空时合并全部非冲突规则，冲突逐条询问覆盖还是跳过。不按仓库情况筛选模板规则，不向子目录复制根模板。项目专有规则写在哪里，也按该文件的规定。

模板不授予操作权限。不要寻找或复制用户全局模板，也不要把个人授权、凭据值或偏好写入仓库。

## 记录用户确立的规则

用户要求记录工作中确立的规则时，只写入用户明确说成规则的内容，无论是在本次请求还是此前的对话中说的。从用户的纠正或一次性任务指令归纳出的只是候选：列出候选及其依据，用户说写入后再写。Agent 操作规则写入其适用层级的 `AGENTS.md`；项目的设计、开发和评审政策写入贡献指南，`AGENTS.md` 里只写简短的操作规则并链接过去。请求只覆盖文档或只覆盖规则时，属于另一部分的规则只报告，不写入。记录的规则与现有规则冲突时报告冲突，不自行取舍。

## 核对与交接

文档部分：核对五个文件和 ADR 目录是否齐全、专题文档是否有入口，逐一比对已有有效内容、命令、链接与实际差异。规则部分：按根到叶的顺序复读结果，核对路径与命令、共同规则是否重复、每个新增子文件是否有明确差异。

交接列出新建的占位文档、实质更新、被取代的旧文档及舍弃的内容、按原样保留的内容、规则的修改或审查发现、对应证据与待确认项。不要把验证日志写入项目文档，也不要把调查记录写成长期规则。
