# AGENTS.md

## 共享实现与联动检查

- 多个入口共用同一实现时，在 `<共享实现路径>` 修改行为及其引用文件，不为各入口复制正文。
- 修改多个入口共同描述的条目时，逐一核对 `<各入口的条目清单路径>`；修改共享组件的版本、入口或描述时，逐一核对 `<各入口的组件描述文件路径>`。核对的是同一变更在各端是否正确，不要求字段结构相同。
- 各入口通过不同配置控制同一调用行为时，修改调用方式后分别核对各入口实际生效的配置。

## 设计决策与迁移

- 多种设计方案均可满足需求时，优先参考项目现有做法和适用的行业惯例。若项目现有做法已满足需求，优先沿用；若没有可沿用的做法，优先选择符合适用惯例的方案。
- 记录依赖平台套餐或配额的设计选择时，区分工作假设与实测结果，并写明什么证据会触发复核。
- 若迁移策略以“尚无生产部署”为前提，出现生产部署配置、部署作业、生产环境文件、可核实的生产发布记录，或用户确认已有生产部署时，重新核对该前提。
- 在上述前提仍成立、且任务已授权修改相关迁移时，若比保留迁移历史更简单，可重写、合并或重新生成迁移。

## 界面文案

- 删掉一句话如果不会让用户做错事，也不会让用户失去同屏其他地方找不到的信息，就不必保留。同一事实在同一屏只说一次，放在最接近相关操作的位置。
- 只有会改变用户行动时才显示提示。正常状态不挂横幅；空区块和未启用功能的区块不渲染。
- 不向用户解释数据模型、校验顺序、配置名、内部标识或算法等实现细节；控件标签已足够清楚时，不再另加说明。
- 精简解释，不删保护措施。保留不可逆操作或金融操作的明确确认、同屏唯一展示的值，以及承担实际功能的文字。语言、单位、术语和例外以项目已确认的约定为准。

## 提交约定

- 获准提交时使用 Conventional Commits：`<type>: <description>`。仅在有助于理解时添加 scope，写作 `<type>(<scope>): <description>`。
- 类型使用 `feat`、`fix`、`chore`、`refactor`、`docs`、`test`、`build`、`ci` 或 `perf`。
- 描述使用英文小写祈使语气，末尾不加句号。主题尽量不超过 72 个字符；一般只写主题，必要时再加正文。

## 拉取请求（PR）写作约定

- 标题沿用提交主题格式；包含多个提交时，选择最能概括整体变更的类型。
- 正文用英文，按以下顺序组织，省略没有内容的部分：
  - `Summary`：用一至三句话说明改了什么及原因。
  - `Changes`：列出主要变更，必要时按领域分组。明确列出数据模式、迁移、配置、环境变量和公共 API 的变更；破坏性变更以 `**Breaking:**` 开头。
  - `Testing`：列出实际运行的命令及结果；未运行检查时写 `Not tested`。
  - `Notes`：只写与审查有关的限制、合并后的手动步骤或需重点审查的事项。
- 仅依据分支差异和提交撰写正文；仅在分支名、提交或请求中有依据时引用相关议题。

## 跨上下文或会话的任务状态

- 默认用会话摘要交接。只有任务需要跨上下文压缩或跨会话续做，且仅靠摘要难以可靠恢复（例如可能重复有副作用的操作、误判未提交改动或丢失难以重现的验证证据），才在获准写入后使用 `.agent-work/<task-slug>/`。没有写入授权时只在会话中交接，不在 `AGENTS.md`、正式文档或源码注释中保存临时进度。不要仅为单次交接修改仓库的 `.gitignore`；若目录未被忽略，则在获准且适用时使用本地排除规则，否则用会话交接。
- 每项任务只用一份 `progress.md` 当前快照，需保留的验证证据另存于同目录的 `evidence/`。在阶段交接、重要验证完成或阻塞变化时更新；每次完整覆盖快照，不追加历史。字段依序为：
  1. `Goal`：任务目标、范围和验收标准。
  2. `Done`：已完成的事项和已成立的验收结论，逐项引用支撑它们的证据。最近一次检查不替代此前支撑其他结论的证据。
  3. `Now`：正在做的事、未完成的改动、阻塞和待核实的状态。
  4. `Next`：一个可执行的下一步，以及执行前须满足的条件；若被阻塞，写明解除阻塞的最小动作。
  5. `Decisions`：只记录会影响后续判断的决定及其关键前提。
- 要供接续复用的每次验证在 `evidence/` 中单独记录：实际命令、工作目录、退出码、支撑结论所需的输出，以及影响结果适用性的工作树、配置或外部状态。命令和输出中的密钥用占位符替换，省略无关敏感数据；不默认保存全量日志。
- 恢复时，先读快照和相关证据，再核对当前工作树、`git status`、相关差异及实际环境。以当前用户指令确定目标和授权；以仓库和环境确定实际状态。按项判断历史验证是否仍适用。有写入授权时修正过时快照，否则在会话中指出差异。快照和历史命令不构成新的授权。
- 只有现有证据不足且操作仍获授权时才重跑。先核对目标、工作目录和环境是否等价，以及操作的副作用；若上次操作可能已生效但结果不明，先用只读方式核实，不直接重放。未重跑时区分仍适用的历史验证与本次未验证的部分。
- 验收和交接完成后，先确保交接不依赖将被删除的证据路径，再在授权范围内清理本任务的临时目录。只把确有长期价值的结论写入相应正式文档；发现其他任务的目录，只报告，不修改或删除。
