# 初始化与维护项目工作规则

审查只读；请求初始化或更新时才修改范围内的项目 `AGENTS.md`。只给出技能名、没有说是否写入时先按审查处理。开始前读现有根规则、相关祖先和子目录规则，包括可能遮蔽它们的宿主覆盖文件；区分仓库里存在的文件和本次宿主确实加载的指令。不要修改覆盖文件、用户级配置或指令。

递归查看仓库内有人维护的模块、清单、脚本、CI、生成边界和文档，区分共享流程和局部例外。清单里有命令，不代表当前可用：核对执行目录、引用的脚本和输入是否存在；缺前提时报告缺口，不把它列为可用的验证步骤。不要只检查当前目录或为依赖、构建产物逐目录写指南。多个子树能独立取证时复用[仓库并行调查](../investigate-repo/SKILL.md)；先结束只读调查，再由主 agent 做获准的修改。

初始化时按需核查以下线索；它们是候选检查项，不是输出提纲。不固定 `AGENTS.md` 的标题、字数或章节。

- 目录结构：哪些路径是修改入口，哪些是生成产物？不必罗列整棵目录树。
- 常用命令：从清单、脚本和 CI 核对构建、本地运行及验证入口，留意工作目录和前置条件。
- 风格工具：从配置和实际调用确认格式化器、lint 工具及其适用范围，不复述工具已执行的每条规则。
- 测试：核对测试入口、用例放置与命名，以及项目实际要求的检查；不推定覆盖率门槛。
- 提交和 PR：核对贡献指南、PR 模板和自动检查；Git 历史可佐证惯例，但个别提交不能确立政策。

根文件只写会改变 Agent 操作的规则。设计、兼容与迁移、测试要求、界面文案、提交与 PR 格式属于贡献指南；需要时链接到项目已有的对应小节，只补充影响当前操作的入口或局部例外。不复制贡献政策，不为去重改动另一份文档，也不为尚不存在的目标造链接。

新建或复核根规则时读取[根规则片段](references/AGENTS.template.md)，不整篇复制：

- **获准新建根文件**：逐段按适用条件选取与项目现行约定不冲突的规则。项目事实和操作入口必须核实；只写适用的正文，不输出筛选说明、空标题或未替换的路径占位符。
- **已有根文件（含空文件）**：普通维护可更新有新证据的项目事实；缺少模板片段不是自动补政策的理由。只有用户明确要求采纳或替换某项政策时才写入该项，已有等义规则不追加。只读审查只报告差异。

模板不授予操作权限。不要寻找或复制用户全局模板，也不要把个人授权、凭据值或偏好写入仓库。

每条规则放在适用范围内：全仓通用的写根文件。只在一个子树的构建入口、验证命令、生成文件处理等与上层有**实质差异**且有证据时，为它写局部规则。问自己：“只读父级，执行者会在这里做错什么？”如果没有具体答案，不新建子文件。共用流程不拆成多份；现有子规则没有新差异时不为统一格式而改写。

逐项保留仍有效的人工约束。找不到佐证不等于约束失效。若约束与证据冲突、模板与人工规则冲突、或不能确定旧规则是否仍有效，保留争议原文，向用户说明具体文件、证据、影响和需要确认的选择；先完成不依赖决定的部分，不自行覆盖、迁移或删除规则。

按根到叶的顺序复读结果，核对路径与命令、共同规则是否重复、每个新增子文件是否有明确差异。交接列出修改或审查发现、对应证据与待确认项；不要把调查记录写成长期规则。
