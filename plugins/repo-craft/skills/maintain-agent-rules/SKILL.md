# 初始化与维护项目工作规则

审查只读；请求初始化或更新时才修改范围内的项目 `AGENTS.md`。只给出技能名、没有说是否写入时先按审查处理。开始前读现有根规则、相关祖先和子目录规则，包括可能遮蔽它们的宿主覆盖文件；区分仓库里存在的文件和本次宿主确实加载的指令。不要修改覆盖文件、用户级配置或指令。

递归查看仓库内有人维护的模块、清单、脚本、CI、生成边界和文档，区分共享流程和局部例外。清单里有命令，不代表当前可用：核对执行目录、引用的脚本和输入是否存在；缺前提时报告缺口，不把它列为可用的验证步骤。不要只检查当前目录或为依赖、构建产物逐目录写指南。多个子树能独立取证时复用[仓库并行调查](../investigate-repo/SKILL.md)；先结束只读调查，再由主 agent 做获准的修改。

初始化时按需核查以下线索；它们是候选检查项，不是输出提纲。不固定 `AGENTS.md` 的标题、字数或章节。

- 目录结构：哪些路径是修改入口，哪些是生成产物？不必罗列整棵目录树。
- 常用命令：从清单、脚本和 CI 核对构建、本地运行及验证入口，留意工作目录和前置条件。
- 风格工具：从配置和实际调用确认格式化器、lint 工具及其适用范围，不复述工具已执行的每条规则。
- 测试：核对测试入口、用例放置与命名，以及项目实际要求的检查；不推定覆盖率门槛。
- 提交和 PR：核对贡献指南、PR 模板和自动检查；Git 历史可佐证惯例，但个别提交不能确立政策。
- 生产标识：项目有生产部署且有证据时，在根文件按名称列出能识别生产或真实账号的对象：数据库和其他数据存储（名称、实例或保存连接串的变量）、部署目标（账号、项目、服务名）、触发生产部署的分支、生产域名，以及生产或真实账号密钥的变量名或文件名。不写密钥值。每项取自已核实的配置、CI、现有文档或用户说明，未核实的标注出来；不声称清单穷尽。

在模板之外，只补充会改变 Agent 操作的项目规则。设计、兼容与迁移、测试要求、界面文案、提交与 PR 格式属于贡献指南；需要时链接到项目已有的对应小节，只补充影响当前操作的入口或局部例外。不复制贡献政策，不为去重改动另一份文档，也不为尚不存在的目标造链接。同一次工作还要运行[项目文档维护](../maintain-project-docs/SKILL.md)时，先运行它，使规则链接到的文档已经存在。

用户要求记录工作中确立的规则时，只写入用户明确说成规则的内容，无论是在本次请求还是此前的对话中说的。从用户的纠正或一次性任务指令归纳出的只是候选：列出候选及其依据，用户说写入后再写。Agent 操作规则写入其适用层级的 `AGENTS.md`；项目的设计、开发和评审政策属于贡献指南，这里只写简短的操作规则，并报告该政策应交给项目文档维护。记录的规则与现有规则冲突时报告冲突，不自行取舍。

根 `AGENTS.md` 采用[根规则模板](references/AGENTS.template.md)，按[模板写入与合并](../../references/template-merge.md)处理：缺失或零字节时全量写入；非空时合并全部非冲突规则，冲突逐条询问覆盖还是跳过。不按仓库情况筛选模板规则，不向子目录复制根模板。

模板不授予操作权限。不要寻找或复制用户全局模板，也不要把个人授权、凭据值或偏好写入仓库。

补充项目规则时，全仓通用的写根文件。只在一个子树的构建入口、验证命令、生成文件处理等与上层有**实质差异**且有证据时，为它写局部规则。问自己：“只读父级，执行者会在这里做错什么？”如果没有具体答案，不新建子文件。共用流程不拆成多份；现有子规则没有新差异时不为统一格式而改写。

找不到佐证不等于人工约束失效。现有规则与仓库事实不符或有效性不明时，说明证据并请用户确认，不自行删除。

按根到叶的顺序复读结果，核对路径与命令、共同规则是否重复、每个新增子文件是否有明确差异。指出 `AGENTS.md` 中混入的任务进度、会话记录和临时 TODO；只在获授权的清理范围内删除。交接列出修改或审查发现、对应证据与待确认项；不要把调查记录写成长期规则。
