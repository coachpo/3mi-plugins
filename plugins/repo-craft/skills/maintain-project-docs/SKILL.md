# 初始化与维护项目文档

审查只报告事实与缺口。只给出技能名、没有说是否写入时先按审查处理。初始化或维护整套文档时，先盘点下列位置、现有文档（包括其他路径、译本和受生成器管理的区域）及有效内容。仅要求改某篇文档时限定到那篇，不借机初始化全仓。

| 项目根下的路径 | 内容归属与证据 |
| --- | --- |
| `README.md` | 项目用途、经清单或入口核实的快速开始、实际存在的文档入口 |
| `ARCHITECTURE.md` | 从实现和调用关系确认的模块边界与关键数据流 |
| `CONTRIBUTING.md` | 贡献者共用的设计、实现、验证与提交流程；项目命令和现行约定从配置、测试入口或已确认的规则核实 |
| `CHANGELOG.md` | 可核实的版本历史与用户可感知变化；提交日期不等于发布日期 |
| `docs/adr/` | 有决策依据时记录背景、选择和原因；当前实现本身不能证明当初为何选择它 |
| `docs/operations.md` | 有配置、流程或有效手册支持的部署、监控、排障、回滚与恢复 |

首次初始化空项目时，`CONTRIBUTING.md` 写入完整模板，其余四个文档建为零字节文件，并创建空的 `docs/adr/` 目录（及必要父目录）。不要给空占位添加标题、示例或隐藏文件。Git 不跟踪空目录；仅当用户要求随 Git 保留时，先核实该仓库的占位惯例，不明确就询问，不能自行决定使用 `.gitkeep`。

维护整套文档时，已有项目也补齐缺失的固定位置。除贡献指南的模板规则外，有证据才填写相应内容；没有证据且目标缺失就创建空占位。已经存在的有效内容不截断、不清空、不为统一格式整篇替换。若目标被不相容的文件类型占用，先报告冲突，不强制覆盖。无历史证据时保持新建的版本记录为空，不补写 ADR。用多个模块的独立材料取证时可复用[仓库并行调查](../investigate-repo/SKILL.md)。

`CONTRIBUTING.md` 采用[贡献指南模板](references/CONTRIBUTING.template.md)，按[模板写入与合并](../../references/template-merge.md)处理：缺失或零字节时全量写入；非空时合并全部非冲突规则，冲突逐条询问覆盖还是跳过。不按仓库情况筛选模板规则；模板只写入贡献指南，不修改 `AGENTS.md`。同一次工作还要运行[项目规则维护](../maintain-agent-rules/SKILL.md)时，先运行本技能，使规则链接到的文档已经存在。

初始化或维护整套文档时，从 README 给有实质内容的文档提供入口；已有入口可用就沿用，不为零字节占位添加导航，也不因空项目已有贡献模板而填充空 README。再次运行时不重复追加同一规则或事实，不改写未变化的文档。旧文档有独立价值时可引用原处；转写保留原件和有效链接。要删除、重命名、用新文档取代旧文档，或变更受管理区域的权威来源，先说明涉及的路径和影响，请用户确认处置方式。

用户要求记录工作中确立的规则时，只写入用户明确说成规则的内容，无论是在本次请求还是此前的对话中说的。从用户的纠正或一次性任务指令归纳出的只是候选：列出候选及其依据，用户说写入后再写。项目的设计、开发和评审政策写入贡献指南；Agent 操作规则属于 `AGENTS.md` 层级，不写在这里，报告它应交给项目规则维护。记录的规则与现有规则冲突时报告冲突，不自行取舍。

审查或维护时，指出零散的进度文件（如 `PROGRESS.md`、`NOTES.md`）、遗留的 `.agent-work/` 目录，以及文档中的进度内容。获准迁移时，把仍有效的持久事实移到固定结构中对应的文档，其余列为删除候选；只审查时只报告拟议的迁移。不删除其他任务的工作目录。

核对五个文件和 ADR 目录是否齐全，逐一比对已有有效内容、命令、链接与实际差异。报告新建的空占位、实质更新、按原样保留的内容和待核实事项；不要把验证日志写入项目文档。
