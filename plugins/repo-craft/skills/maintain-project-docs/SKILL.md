# 初始化与维护项目文档

审查只报告事实与缺口。初始化或维护整套文档时，先盘点下列位置、现有文档（包括其他路径、译本和受生成器管理的区域）及有效内容。仅要求改某篇文档时限定到那篇，不借机初始化全仓。

| 项目根下的路径 | 内容归属与证据 |
| --- | --- |
| `README.md` | 项目用途、经清单或入口核实的快速开始、实际存在的文档入口 |
| `ARCHITECTURE.md` | 从实现和调用关系确认的模块边界与关键数据流 |
| `CONTRIBUTING.md` | 从项目配置、测试入口或明确约定核实的环境、编码、测试与 PR 流程 |
| `CHANGELOG.md` | 可核实的版本历史与用户可感知变化；提交日期不等于发布日期 |
| `docs/adr/` | 有决策依据时记录背景、选择和原因；当前实现本身不能证明当初为何选择它 |
| `docs/operations.md` | 有配置、流程或有效手册支持的部署、监控、排障、回滚与恢复 |

**先固定结构，再决定写什么。** 首次初始化空项目时只创建五个零字节文件和空的 `docs/adr/` 目录（及必要父目录）。不要放标题、待办清单、示例版本、示例 ADR 或隐藏文件。Git 不跟踪空目录；仅当用户要求随 Git 保留时，先核实该仓库的占位惯例，不明确就询问，不能自行决定使用 `.gitkeep`。

已有项目也补齐缺失的固定位置。先读后改：有证据才填写相应部分，没有证据且目标缺失就创建空占位；已经存在的有效内容不截断、不清空、不为统一格式整篇替换。若目标被不相容的文件类型占用，先报告冲突，不强制覆盖。无历史证据时保持新建的版本记录为空，不补写 ADR。用多个模块的独立材料取证时可复用[仓库并行调查](../investigate-repo/SKILL.md)。

初始化或维护整套文档时，从 README 给有实质内容的文档提供入口；已有入口可用就沿用，不为零字节占位添加导航。再次运行时只补漏或修正有新证据的部分，不重复追加同一事实、不改写未变化的文档。旧文档有独立价值时可引用原处；转写保留原件和有效链接。要删除、重命名、用新文档取代旧文档，或变更受管理区域的权威来源，先说明涉及的路径和影响，请用户确认处置方式。

核对五个文件和 ADR 目录是否齐全，逐一比对已有有效内容、命令、链接与实际差异。报告新建的空占位、实质更新、按原样保留的内容和待核实事项；不要把验证日志写入项目文档。
