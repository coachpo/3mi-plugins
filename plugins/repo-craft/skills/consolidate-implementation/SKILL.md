# 清零式收敛

先辨别请求：审查或提案只读；提及本技能、抱怨重复、要求“清理一下”均不构成收敛请求。只有用户明确要求实施收敛且目标设计已确认，才开始改动。不根据实现的新旧、名字、默认开关或看似更好的设计猜哪条路径胜出。

## 明确要保留的东西

对照用户决定与仓库，查明目标实现、影响范围、实际调用方、仍须支持的契约、可退役的路径及移除授权。检查公共入口、配置和动态注册、脚本、CI、读写双方、文档及仓库外已知消费者。无静态引用不足以证明可以删除。涉及持久化时，先核实数据库目标、保留数据、升级、恢复和留存要求；不涉及数据库则不引入数据库任务。

遇到设计未定、契约不清或移除未获授权，把缺少的决定、证据和影响说清楚，问最小的问题。保留受影响的路径，只继续与之无关且已获授权的部分；不能把“缩减范围”悄悄写成“已完成”。

## 分开判断基线文件与数据操作

- **仓库基线**：检查现行建库入口、迁移链、受支持的实际环境与升级/恢复依赖。得到基线替换及移除授权后，让每个独立数据库从一种权威入口得到最终表结构、约束、索引和必要初始数据；不是强制合并成一个文件。若仍有受支持环境依赖既有历史或无法确认，先说明冲突并请用户决定。不要直接删迁移、另造并行基线或把尚未验证的历史描述为废弃。
- **运行数据库操作**：改基线不是对任何实例执行 SQL、重置、迁移或重灌的授权。先核对命令实际连接的目标、数据来源和保留要求；名称中含 local、dev 或 staging 不能证明数据可丢弃。对远端非生产目标的写入须另有针对该目标的授权；对生产的每项迁移或破坏性操作均须用户明确授权具体目标及操作。使用真实账户凭据也须单独获得用户对本次使用的明确指示。未确认时只读核实，不连接未知目标试错。

## 切换与验证

先切换实际调用方、配置及运行入口，保留仍有效的行为断言并更新文档。仅在确认不再需要**且**获准移除后，清除旧实现、兼容层、过渡开关、重复路径、废弃迁移和中间产物。不要顺手删除不相关的工作、保留义务覆盖的资料或仅靠仓库搜索无法排除的外部契约。

走一遍最终调用路径，运行与契约相符的最小检查；再复查调用方、配置、测试、文档和动态入口中退役名称的剩余引用。改了基线时，在获准的隔离实例上验证正常建库和核心读写；有保留数据或升级/恢复契约时，空库验证不能替代相应旧状态的验证。没有合适实例则报告缺口，不用远程目标代替。

按已验证、未验证、受阻分开交接：列实际命令、结果、仍保留的路径及理由，以及缺的证据或授权。仅在最终路径及所需基线、契约都经验证且已授权的退役项确实退役后，才报告收敛完成。
