# 持久化数据清理

这些判据是对[精简仓库](../SKILL.md)中保全义务的补充。

- 枚举该存储字段或变体的全部写入点。若写入只产生常量值，或从不写入它，把处理新数据上不可能出现的值的读取方视为既有数据路径。检查受影响的数据能否丢弃。指出仓库无法确立的可丢弃性事实，并把依赖它的候选项归为一组。
- 把每个候选项归为可删除、看似历史但仍在使用，或未决。按可达性判断，不按标签：名字带 legacy 的变体可能仍在被写入，一个普通的空值分支可能只服务于既有数据。
- 删除已获授权且改动带来净维护收益时，在受影响的类型、校验和存储约束中让退役的状态无法表示，而不是只删掉读取分支。
- 清理会改变所接受的持久化形态时，查明哪些形态将不再被接受、哪些既有数据会变得无效。只要会被判为无效的数据中有必须保留的，或其可丢弃性未决，就停止受影响的改动。收紧新输入的授权，不等于授权使既有数据失效。旧数据可丢弃，并不免除[现行契约边界](../SKILL.md#确定范围与授权)，也不授予迁移或部署的许可。重建、迁移、导入、发布和部署不在本技能范围内。
