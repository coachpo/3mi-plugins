# 约束索引格式

`CONSTRAINTS.md` 登记用户纳入管理的项目约束及其变更记录。建立、修改和核对索引时遵循本文件。

## 文件结构

引言、约束条目、变更记录三部分依次出现：

```markdown
# 项目约束

本文件登记本项目明确要守住的约束，由 repo-craft 的 `constraint-manager` 技能维护。条目有 `Source` 时条文以它指向的文档为准，没有时以条目本身为准。`active` 的条目有效；`disputed` 的条目有效性待定，涉及它时先问用户；`superseded` 和 `retired` 的条目已失效，只作记录。新立或变更约束一律用该技能进行：先给出提案，经用户同意后才写入。

## 约束

### C-001 生产数据库使用 PostgreSQL

- Status: active
- Scope: backend/
- Source: [docs/adr/0001-database.md#决策](docs/adr/0001-database.md#决策)
- Also in: [README.md#技术栈](README.md#技术栈)

生产数据库必须使用 PostgreSQL。

### C-002 内存占用上限

- Status: active

服务常驻内存占用不超过 200 MB。

## 变更记录

- CR-001 · 2026-11-19 · adopt · C-001
- CR-002 · 2026-11-19 · add · C-002
  - 理由：目标设备只有 512 MB 内存。
- CR-003 · 2026-11-20 · relax · C-002
  - 原条文：服务常驻内存占用不超过 100 MB。
  - 理由：引入本地缓存后需要约 150 MB。
```

标题、引言和子项标签的措辞可以换成项目文档的语言；条目标题行的编号、字段名、状态值和变更记录的操作名是固定的。

## 条目

条目由一个三级标题、紧随其后的字段列表和一段陈述组成，三者之间各空一行。

- **标题行** `### C-<编号> <标题>`：编号从 `C-001` 起，三位数字，不足补零，超过 999 后自然增长。新编号取文件里出现过的最大编号加一，变更记录里出现过的也算；编号一经分配不改、不复用。标题是给人看的，可以改，引用条目一律用编号。
- **字段** 每行一个，写作 `- 字段名: 值`，按下表顺序出现；不适用的字段整行省略，不写“无”。
- **陈述** 一到两句、脱离上下文也读得懂的话。有出处时尽量取出处原句，原句脱离上下文读不通才改写；没有出处时它就是约束条文，用用户的原话或经其确认的措辞。

| 字段 | 必填 | 取值 |
| --- | --- | --- |
| `Status` | 是 | `active`、`disputed`、`superseded` 或 `retired` |
| `Scope` | 否 | 约束适用的子树：相对仓库根、以 `/` 结尾的路径，多个用逗号分隔。省略表示全仓 |
| `Source` | 否 | 一个 Markdown 链接，指向条文所在的文档和离它最近的标题锚点，路径相对索引文件。约束只存在于索引时省略 |
| `Also in` | 否 | 重述同一条约束的其他位置，逗号分隔的 Markdown 链接。变更时这些位置要一起改 |
| `Supersedes` | 否 | 本条目取代的条目编号 |
| `Superseded by` | `superseded` 时必填 | 取代本条目的条目编号 |
| `Conflicts with` | 否 | 与本条目矛盾的条目编号，多个用逗号分隔。矛盾的另一方不是条目时省略，在变更记录里说明 |

同一条约束在多处出现时，出处选记录了这项决定及其理由的那一处，通常是 ADR；没有的话选按固定文档结构应当承载它的文档；其余位置都算重述。所在文档没有标题时，链接只写到文件。

条目不删除。约束废止或被取代后，条目保留当时的陈述，删去 `Source` 和 `Also in`；条文原来在哪里、如何处理，记在变更记录里。

## 状态

| 状态 | 含义 | 何时进入 |
| --- | --- | --- |
| `active` | 有效 | 纳入、新立，或争议裁决后保留 |
| `disputed` | 有效性待定，涉及它的工作先问用户 | 与其他条目或文档矛盾，或出处被绕过流程改动，而用户决定先搁置 |
| `superseded` | 已被另一条目取代 | 应用 `replace` |
| `retired` | 已废止 | 应用 `remove` |

`superseded` 和 `retired` 是终态：重新盘点时遇到它们的条文不重新启用。用户要恢复一条已废止的约束时按新立处理，建新条目。

## 变更记录

每次经用户同意的写入追加一条，旧的在前，不改写已有记录。格式是 `- CR-<编号> · <日期> · <操作> · <条目>`，需要时带缩进的子项。编号规则同条目，在应用时分配；日期是应用当天，写作 `YYYY-MM-DD`。

| 操作 | 含义 | 条目栏 | 子项 |
| --- | --- | --- | --- |
| `adopt` | 纳入文档里已有的条文 | 纳入的条目，可多个 | 无 |
| `add` | 新立没有出处的约束 | 新条目 | 理由 |
| `modify` | 收紧或澄清，编号不变 | 该条目 | 原条文、理由 |
| `relax` | 放宽，编号不变 | 该条目 | 原条文、理由 |
| `replace` | 以新条目取代旧条目 | `C-旧 → C-新` | 理由 |
| `remove` | 废止 | 该条目 | 理由、原出处如何处理 |
| `dispute` | 标为待定 | 相关条目 | 矛盾所在 |
| `resolve` | 争议裁决后恢复为有效 | 该条目 | 裁决 |

`原条文`逐字保留变更前的陈述。`理由`写用户给出的理由；用户没有说就写“未说明”，不代拟。修复链接、随出处的措辞同步陈述这类不改变含义的维护不记变更。

## 核对清单

1. 条目编号唯一，变更记录编号唯一，格式正确。
2. 每个条目有 `Status`，取值是四个之一；字段名都在上表内，每行一个。
3. `active` 和 `disputed` 条目的每个 `Source`、`Also in` 链接：文件存在，锚点对应该文件里的一个标题，那里确有这条约束的条文，含义与陈述一致。
4. `superseded` 条目有 `Superseded by`，所指条目存在并以 `Supersedes` 指回；`Conflicts with` 互相指向。
5. `superseded` 和 `retired` 条目不带 `Source` 和 `Also in`，并在变更记录里有对应的 `replace` 或 `remove`。
6. 变更记录引用的条目都存在；`modify` 和 `relax` 带原条文。
7. 没有两个 `active` 条目陈述同一条约束且适用范围重叠。
