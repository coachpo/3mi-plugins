# 项目文档详细规则

本文件承载 `write-project-docs` 的详细文档契约。单文档任务只读取相关章节；完整初始化、归并或迁移读取全文。

## 双语路径与专项文档

产品、架构、开发规范和源代码规模四类权威使用同一种语言的路径，语言按主技能「项目文档语言」判定。

同一权威不长期保留两个变体，也不用重定向、符号链接或重复正文并行暴露。两个变体同时存在时，按主技能的冲突分支先取得路径决定和清理授权。

保留独立有价值的专项文档，例如 API 参考、数据字典、UI/UX 指南、设计系统、测试策略、安全设计、研究、发布和运维文档；不为模板对称创建空文档。生成或外部维护的文档保持不变，可核实时记录其更新机制；无法核实的文档保持不变，不传播其中不确定的内容。

## 归并与迁移

标准映射：

- `docs/INDEX.md` → `docs/README.md`。
- 未选中的双语变体 → 同一权威的选定路径。
- 安装和普通启动命令 → `README.md`。
- 开发环境、开发启动、测试、检查和构建命令 → `CONTRIBUTING.md`。
- 生命周期、部署、用户、数据和兼容政策 → `STATUS.md`。
- 项目特有代码风格、评审要求和技术实现规则 → 选定的开发规范路径。
- 模块职责、依赖方向和具体例外 → 选定的架构路径。
- 与项目无关的规模与职责规则 → 选定的源代码规模规则路径。
- 旧规模指南中的项目特有规则 → 开发规范，或架构文档的 `结构性例外` 章节。

改动规范路径前盘点全部引用。旧文档的独有、已核实且仍有效的信息全部吸收后，才能列为弃用候选。修复本次编辑影响的文档链接。对现有且可编辑的根 `AGENTS.md`，`update_agents_navigation.py` 只改写托管区块外可见 Markdown 链接目标中整段精确匹配的旧路径，并保留其他技能的托管区块；正文、代码围栏、HTML block、绝对路径、外部 URL 和子串匹配都不改写。正文中的旧路径只报告，交给用户判断它是过时项目引用还是合法的外部仓库引用。源代码、配置、CI、测试、子目录 `AGENTS.md` 和其他指令文件中的旧路径也只报告，不默认修改。

`CLAUDE.md` 不属于 canonical 文档迁移或校验范围；本技能及其脚本不创建、规范化或要求该文件，也不因其缺失或内容形式产生迁移警告。

未经明确清理授权，不删除、移动、归档或重组现有文档。重定向、符号链接、重复共享条款、并行托管区块和同一权威的中英文双版本不作为长期迁移状态。

## 各文件要求

### `README.md`

包含项目名和一句话说明、带醒目 `STATUS.md` 链接且标明“以 `STATUS.md` 为准”的派生状态摘要、已验证的安装和普通启动命令，以及文档索引、产品、架构和贡献文档链接。不复制其他文档正文，也不维护测试、检查或构建命令。

### `STATUS.md`

记录一个必填静态开发档位，以及可验证的生命周期阶段、部署状态、外部用户状态、不可丢弃数据状态、稳定性与兼容性承诺、允许和禁止的变更、可验证时的最近评审日期，以及触发再次评审的条件。只有直接项目证据或用户指令成立时，才写入“未部署”“没有外部用户”或“没有不可丢弃数据”。

`STATUS.md` 必须包含全文件唯一、Markdown 可见的精确控制行：中文 `开发档位：<TOKEN>`，英文 `Development Tier: <TOKEN>`，其中 token 只允许 `YOLO_LOCAL`、`EXPERIMENT`、`MVP`、`PILOT`、`PRODUCTION`、`MAINTENANCE` 或 `RETIRED`。代码围栏或 HTML block 内的同文不生效；缺失、畸形、重复、冲突、未知 token 或写成另一种语言都是错误。开发档位实质改变后续执行默认值，只有用户明确选择或既有精确档位支持时才写入；`YOLO_LOCAL` 还必须由用户明确声明可丢弃本地工作区、无真实数据、无生产凭据、无外部用户/流量且无外部副作用。

生命周期、部署、用户、数据和兼容事实仍用普通自然语言表达，不增加其他控制键。开发档位只选择静态执行默认值，不能据此推断未部署、没有用户、没有真实数据、允许重置数据或允许破坏兼容；`YOLO_LOCAL`、`EXPERIMENT` 和 `MVP` 档位以档位默认形式永久豁免安全、隐私、数据、密钥与凭据管理、兼容、审计/监控/SLO 及法规合规要求的主动投入（完整定义见[静态开发档位契约](development-tiers.md)），豁免不证明“没有真实数据”“无需任何保护”或“允许破坏兼容”，也不覆盖用户要求、已接受 GOAL、硬规则/不变量或 `STATUS.md` 明确禁止事项；交付目的及其范围、非目标和验收仍属于产品文档。

旧 `MVP 快速验证模式：启用` 或英文等价行只在明确获准维护 `STATUS.md` 的迁移中改写为 `MVP` 档位。旧“未启用”、旧状态缺失或其他旧写法不能推断新档位，必须由用户显式选择；组合脚本不修改 `STATUS.md`，遇到旧状态时失败关闭。

上述状态事实本身不能证明允许破坏性重构、数据重置或放弃兼容性。保留以下技能共享政策：仅当项目仅在本地、未部署、没有外部用户且没有不可丢弃数据全部已核实，并且没有更高优先级的用户决定或已有项目政策反对时，记录 API、配置和数据库模式不保证向后兼容，允许破坏性重构和本地数据重置，不为旧版本创建兼容层，且适用质量检查仍须通过。其他场景只有用户指令或已有项目政策直接支持时，才记录允许或禁止的变更。

### `CONTRIBUTING.md`

包含已核实的开发环境与依赖设置、开发启动、测试、检查和构建命令、开发工作流、由 `STATUS.md` 档位选择的当前开发策略，以及共享设计原则、实现原则和完成定义。它是静态执行默认值、共享规则和完成定义的入口；链接状态、产品、架构、开发规范和规模规则，不把档位策略冒充事实权威，也不复制项目特有技术规则或其他文档正文。

基础共享区块始终来自 `assets/<lang>/` 下的 CONTRIBUTING 基础 asset，每个允许 token 在同目录有一份 `CONTRIBUTING-tier-<token-slug>.md` 静态策略 asset。`scripts/update_contributing.py` 验证当前语言完整七档 catalog，把选中策略放在 `shared-contributing` 托管区块最前方，再保留通用设计原则、实现原则和完成定义。策略固定输出摘要、“本档位必须完成”“默认不投入”“不可越过的边界”和“切换条件”；档位默认不投入只约束可选工作，不覆盖用户要求、硬规则/不变量、真实数据、现有用户、兼容承诺或受影响路径必需检查。`YOLO_LOCAL`、`EXPERIMENT` 和 `MVP` 档位把安全、隐私、数据、密钥与凭据管理、兼容、审计/监控/SLO 及法规合规要求豁免为永久档位默认不投入，包括按可达风险驱动投入的约束；豁免不得用于覆盖上述保留来源，也不得据其记录“没有真实数据”“无需任何保护”或“允许破坏兼容”。

静态映射的完整契约见 [静态开发档位契约](development-tiers.md)。不再存在项目特定 JSON handoff、来源摘要或独立策略 updater。更新脚本在新档位已有效时可原子移除结构合法的旧 `derived-iteration-strategy` 区块，并把旧共享 MVP H3 替换为选中静态策略；旧 marker 歧义、旧标题位于托管区块外或托管标题结构漂移时保持文件不变并报告错误。运行更新后再用 `validate_project_docs.py` 验证语言、档位、完整 catalog、组合结果和边界。

### `docs/README.md`

仅作路由页。列出规范文档的选定路径和权威范围，说明 `CONTRIBUTING.md` 是由 `STATUS.md` 开发档位选择的当前开发策略、开发工作流、共享原则和完成定义入口，而不是事实权威；开发规范是项目特有技术与实现规则的权威，规模规则是独立专项策略；再列出已核实的专项、生成或外部文档及用途。不重复产品、状态、架构或开发事实。

### 产品文档

`docs/产品说明.md` 或 `docs/product.md` 仅在可核实时包含问题、目标用户、目标与当前交付目的、明确非目标、功能范围、核心用户流程与需求、验收标准、已知约束或假设。“为了演示”等意图仍在此形成最小可验证事实；不要在产品文档复制开发档位策略正文。

### 架构文档

`docs/架构说明.md` 或 `docs/architecture.md` 描述当前设计而非理想蓝图：系统边界与外部依赖、模块及职责和数据生命周期、依赖方向、数据模型与流、接口、技术栈、安全边界、本地运行模型、质量属性、风险限制和相关 ADR。具体架构或安全例外记录准确范围、理由、补偿控制、验证方式及到期或可测试退出条件。不放通用编码策略。

### 开发规范

`docs/开发规范.md` 或 `docs/development-rules.md` 以且仅以一个本语言的 H1 标题开头（中文 `# 开发规范`，英文 `# Development Rules`），随后立即放置规模规则托管区块。区块之后提供指向 `CONTRIBUTING.md` 共享规则的规范链接，并只写已核实的项目特有代码风格、评审要求和技术实现规则。责任组件、边界、依赖方向和具体例外引用架构文档；不重复共享原则、完成定义、例外正文或规模阈值。只有标题和托管区块是有效状态，只有标题则无效。

### 源代码规模规则

`docs/源代码规模与职责规则.md` 或 `docs/source-code-size-and-responsibility-rules.md` 以 `assets/<lang>/` 中对应语言模板的渲染结果作为完整文档，只替换声明的路径变量，不添加项目名、技术、例外、命令或局部阈值。

## ADR 例外

只有用户明确要求 ADR 工作时，才创建、重写、移动或整理 ADR。保留现有 ADR，并从架构文档链接相关记录。新 ADR 记录状态、日期、上下文、备选方案、决定和后果；除非用户要求 ADR 审查，不报告未被记录的决定。
