# 当前迭代策略契约

本契约规定如何把自然语言项目状态和交付意图转换成当前执行策略。语义判断由调用技能的代理完成；脚本只校验结构、渲染独立托管区块并绑定来源摘要。不得把“开发中”“为了演示”等词做成枚举、关键词分类器、精确状态行或新的硬开关。

## 权威事实与派生结果

- `STATUS.md` 是生命周期、部署、外部用户、不可丢弃数据、兼容政策及允许/禁止变更的唯一权威。
- 产品文档是当前交付目的、目标流程、范围、明确非目标、可观察验收和已知约束的唯一权威。
- 架构文档和开发规范分别约束可达技术风险、安全边界与项目特有实现规则。
- `CONTRIBUTING.md` 的“当前迭代策略”只是以上事实的派生执行默认值，回答本轮采用什么策略、做什么、不主动投入什么、哪些边界不能降低及何时重新推导。它不成为事实权威，不扩大用户授权，也不覆盖当前任务或活动 Goal。

用户在请求中给出新的明确事实时，先将其最小化写入对应权威文档，再推导策略。无法从权威文档或用户指令核实的事实保持未知；不得从“开发中”或“演示”推断未部署、没有用户、没有真实数据、允许重置数据、允许破坏兼容或不需要安全保护。

持久区块的语义输入只能是元数据绑定的上述四份文档。本次请求、活动 Goal、当前 diff、临时工作区状态或 Reviewer 发现可以在当前任务中覆盖暂缓默认，但不是未绑定的持久策略输入；若它们需要持续影响后续迭代，先把已核实事实或规则写入对应权威文档，再重新推导。不得把这些瞬态输入直接编码进 JSON handoff。

`CONTRIBUTING.md` 同时存在启用态 MVP H3 时，消费阶段策略还要应用其中的三层范围覆盖。“明确不做”只排除与核心验证无关的专项治理、体系扩建、兼容层与全量兼容回归、仓库级全量检查、默认门禁和生产加固；已有兼容承诺和仓库必需检查本身不构成排除授权，受影响路径或核心验收所需部分仍执行。“可推迟”的每项具体工作必须同时记录当前依据和可观察重评条件；“仍是约束”限制可选动作但不自动增加专项工作。该覆盖不进入策略 JSON，不改变来源摘要，单独切换 MVP 时也不重写策略字节。

## 推导方法

先明确当前交付目的和可观察成功条件，再逐项判断候选工作。一个事项至少满足以下一个正向触发条件，才能进入“本轮必须完成”或“不可降低的边界”：

1. 当前验收、核心流程或可重复交付依赖该事项；
2. 权威状态中的当前部署、用户或数据，或架构文档中的当前设计使相应风险真实可达；
3. 权威产品范围、兼容承诺或适用项目规则明确要求；
4. 权威文档所述当前实现触及安全、隐私、权限、数据完整性或不可逆状态边界；
5. 仓库已有适用且必需的检查、约束或不变量要求它。

没有正向触发证据的事项不自动加入本轮，也不因为“将来可能发生”而调查、设计或验证。只有某项与当前工作相邻、容易被误纳入且已有明确延期依据时，才写入“本轮不主动投入”；每项必须同时记录依据和可观察的重评条件。不要穷举不可达、纯假设或无限未来事项，也不要生成“无”“待确认”或缺失信息清单。

未知不等于不存在。只有未知事实可能实质改变当前策略、用户授权或高后果边界时，才做一次最小取证或询问一个最小问题；否则保持策略窄而准确。当前事实、目的、验收、部署/用户/数据、兼容承诺、可达风险或适用规则变化时重新推导，而不是沿用旧区块。

## 演示场景的判定示例

“项目开发中，当前为了演示”且没有性能验收或可达负载风险时，通常推导为：采用可重复、易观察的端到端演示闭环；跑通实际演示路径、可见结果和必要冒烟/功能验证；不主动投入压测、容量规划、高可用或生产级可观测性；当出现吞吐、并发、延迟验收、真实流量或生产部署时重评。

这不是关键词默认值，以下证据必须改变结论：

- 若目的就是演示性能/容量，或验收指定并发、吞吐、延迟指标，压力或负载验证属于当前必做。
- 若是公网演示、已有外部用户或使用真实/不可丢弃数据，实际触及的认证、授权、隐私、权限和数据完整性保护由这些可达事实触发阶段策略；当前变更触及兼容、持久化、权限或失败恢复边界时，相应的最小反例与恢复验证同样由权威事实触发。
- 上述推导不读取 MVP 开关。若 `CONTRIBUTING.md` 另有启用态 MVP H3，下游消费时才应用三层范围覆盖：已经影响核心验收的部分仍执行；非核心专项、全量回归或默认门禁明确排除，或在写明当前依据及真实用户、真实/不可丢弃数据、外部流量、兼容验收、对应风险等可观察重评条件后推迟。已有兼容承诺和明确禁止事项仍限制可选动作。
- 只有 MVP 精确状态行改变时，不重新解释交付目的，阶段策略字节保持不变。

## 结构化投影

将语义结果编码为 UTF-8 JSON，并通过标准输入交给：

```bash
python3 <skill-dir>/scripts/update_iteration_strategy.py <project-root>
```

输入只能包含以下字段；`language` 必须与项目文档语言一致，所有字符串都使用该语言：

```json
{
  "schemaVersion": 1,
  "language": "zh",
  "strategy": "采用的执行策略及优先级",
  "doNow": ["本轮必须完成且可观察的事项"],
  "defer": ["本轮不主动投入的相邻事项；依据：没有当前正向触发证据；重评：出现相应可观察事实时"],
  "guardrails": ["当前触及且不可降低的边界或必需检查"],
  "rederiveWhen": ["使本策略失效并需要重新推导的变化"]
}
```

`language` 只允许 `zh` 或 `en`；`strategy` 必须是一个非空单行字符串，`doNow`、`guardrails` 和 `rederiveWhen` 必须是非空数组；`defer` 可以为空，此时整个对应小节省略。整个 JSON 最多 64 KiB，每个数组最多 32 项，每个字符串最多 2,000 个 Unicode code point；字符串不得为空、首尾含空白或形成 CommonMark ATX 标题/围栏代码块开始行，也不得包含换行、除内嵌 tab 外的 C0/C1 控制、surrogate 或 Unicode 双向方向控制字符；数组内不得重复。普通比较符 `<`、`>` 可用，投影时会与 `&` 一起转义为安全的 Markdown 文本。每个 `defer` 字符串都要同时表达事项、依据和重评条件。JSON 必须可用 UTF-8 唯一键解析，输入拒绝缺失、未知或重复字段，尤其拒绝 `mvpMode`、`mvp` 或其他 MVP 控制字段。脚本不得自行解释自然语言、补全项目事实或改写共享/MVP 区块。

投影区块使用独立的 `derived-iteration-strategy` marker，并置于 `shared-contributing` 区块之前。区块元数据绑定规范化的 `STATUS.md`、选定产品文档、架构文档和开发规范来源摘要以及可见内容摘要；每个项目只从摘要中排除与其文档语言一致、Markdown 可见且唯一的精确 MVP 控制行，围栏或 HTML block 内的同文字面不排除，另一语言、畸形、重复或冲突状态则停止写入。规范化后还把文件末尾统一为一个 LF，使精确控制行在有无末尾换行的合法缺失态之间切换也保持正交。因此单独切换有效 MVP 状态不会使策略漂移，其他 `STATUS.md` 内容变化仍会使摘要漂移。来源变化后必须重新完成语义判断并重投影，不能只刷新摘要；既有策略项目先重投影（或授权时先 `--remove`）再运行共享/MVP updater，首次新增策略则先建立共享区块再投影。

只有当前策略已不再适用、权威事实又不足以形成替代策略，且本次写入授权包含该维护时，才运行：

```bash
python3 <skill-dir>/scripts/update_iteration_strategy.py <project-root> --remove
```

验证器允许旧项目没有策略区块；一旦区块存在，就校验语言标题、marker 唯一性、与共享区块不重叠、来源摘要、内容摘要及本地链接。机械验证通过只证明投影完整且来源未漂移，不证明代理的自然语言判断正确。

## 下游消费

- 工程类 Goal 读取权威事实、当前策略和实际存在的 MVP H3，把与用户请求相交的必做项投影到结果、范围和连续 `C*`，把“仍是约束”投影到约束；启用 MVP 时，把容易误纳入的“明确不做”投影为范围排除，把相关“可推迟”连同当前依据和可观察重评条件投影为范围排除或重评条件。
- 验证配置以当前目的、Goal 和核心验证结论设计 base catalog。启用 MVP 时只纳入使结论可观察、可复现以及受影响路径或核心验收明确要求的检查，不把仓库级全量检查、默认门禁或生产加固自动加入 catalog；`full` 表示执行当前 catalog 的全部 case，不表示验证所有可以想象的未来场景，`quick` 仍只是诊断子集。
- 用户要求、活动 Goal、硬性不变量、有证据表明核心结论无效的 Reviewer finding，或“可推迟”中记录的可观察重评条件成真时，可以重新纳入相关工作。已有兼容承诺和仓库必需检查仍限制适用动作，但只有其非核心专项、全量验证或默认门禁可被排除；暂缓项和“明确不做”不生成 exclusion ID、digest 或 audit 覆盖证明，本契约不新增 audit 级 coverage-exclusion 机器合同。
- 策略与权威事实冲突或摘要漂移时，以权威事实为准并停止消费旧策略；活动 Goal 已建立后，不自动改写其结果、范围、约束或 `C*`，而是按 Goal 兼容性规则处理。
