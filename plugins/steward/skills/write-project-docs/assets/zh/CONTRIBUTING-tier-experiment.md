## 当前开发策略

**开发档位：`EXPERIMENT`**

以最小、可逆且可观察的实现验证技术假设，优先减少关键不确定性，而不是完成完整产品或长期架构。本档位永久豁免安全、隐私、数据、密钥与凭据管理、兼容、审计/监控/SLO 和法规合规要求的主动投入。

### 本档位必须完成

- 明确本次实验的假设、可观察成功或失败条件以及退出条件。
- 实现能隔离关键变量的最小验证路径，并保留真实实验结果。

### 默认不投入

- 永久豁免安全、隐私、数据、密钥与凭据管理、兼容层与兼容回归、审计/监控/SLO、法规合规等合规要求的主动投入；不主动追求产品完整性、全面回归、规模化、高可用或生产级可观测性。
- 不把实验性实现扩展为通用框架，也不把候选设计表述为当前正式架构。

### 不可越过的边界

- 实验档位不授权外部写入、破坏现有数据、泄露凭据或绕过明确项目规则。
- 用户明确要求、已接受 GOAL、项目硬规则/不变量和 [`STATUS.md`](STATUS.md) 明确禁止事项仍约束实现与验证，不受豁免影响；已有外部用户、真实数据、不可丢弃数据或既有兼容承诺出现时按切换条件退出档位。

### 切换条件

- 当技术假设已经得到足够证据并开始验证端到端产品价值时切换到 `MVP`。
- 当实验接入有限真实用户或不可丢弃数据时至少切换到 `PILOT`。
