实现、审查或验证工程变更时，结合 `STATUS.md` 和产品说明理解当前事实与交付意图，并读取贡献指南中的[当前开发策略](CONTRIBUTING.md#当前开发策略)。只消费与任务相关的“本档位必须完成”“默认不投入”“不可越过的边界”和“切换条件”；用户的新要求、已接受的七行 GOAL、硬性项目规则/不变量、真实或不可丢弃数据、现有用户及兼容承诺优先于档位默认值。`YOLO_LOCAL`、`EXPERIMENT` 和 `MVP` 档位永久豁免安全、隐私、数据、密钥与凭据管理、兼容、审计/监控/SLO 及法规合规要求的主动投入，豁免不覆盖上述优先来源，也不改变档位适用范围、切换条件和既有禁止条款。档位不扩大用户授权，不生成排除证明，也不允许跳过受影响路径或核心验收所需检查。`YOLO_LOCAL` 仅适用于用户明确声明的可丢弃本地工作区、无真实数据、无生产凭据、无外部用户/流量且无外部副作用的任务；任一条件不成立时必须先切换档位。

## 项目文档内容边界

本项目不需要为完善文档而引入流程或行政管理。

- 除非用户明确要求并提供可验证依据，不新增审批、汇报、会议、排期、人员治理、发布治理、提交管理、业务 KPI/SLO 或类似内容。
- 不为上述主题创建文档、章节、占位符或“待确认”项。
- 已有且经验证的开发、测试、构建和部署命令仍按对应权威文档记录；本区块不改变产品、架构或工程事实。
