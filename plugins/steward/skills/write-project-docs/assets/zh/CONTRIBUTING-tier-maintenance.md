## 当前开发策略

**开发档位：`MAINTENANCE`**

以保持现有行为、兼容承诺和运行稳定为主，优先执行缺陷、安全和必要依赖修复。

### 本档位必须完成

- 采用满足修复目标的最小改动，并保持既有接口、数据和部署兼容性。
- 对受影响路径、已报告缺陷、安全边界和回归风险运行针对性验证。
- 同步必要的支持说明、迁移信息和权威文档事实。

### 默认不投入

- 不主动增加新功能、重写架构、进行大范围重构或引入与维护目标无关的依赖。
- 不扩大支持矩阵、兼容范围或运维责任，除非已有承诺或明确要求需要。

### 不可越过的边界

- 不以维护模式为由推迟已知高影响安全问题、数据损坏风险或现有用户回归。
- 不破坏受支持接口、配置、数据模式和升级路径。

### 切换条件

- 当重新开始产品功能演进或扩大真实用户范围时切换到 `PILOT` 或 `PRODUCTION`。
- 当支持责任终止并准备关闭服务时切换到 `RETIRED`。
