# 交接文件契约

GOAL 正文有 4,000 字符硬上限，由 [`goal_contract.py`](../scripts/goal_contract.py) 机器校验。正文压缩到只剩背景材料仍未通过校验，或用户在本次请求里明确要求把上下文写成文件时，把这部分背景写进项目内一份交接文件，正文只留一句引用。

其余情况不创建，否则每次起草都会留下一份文件，项目里很快就是一堆没人引用的背景。

[`draft-consensus-goal`](../skills/draft-consensus-goal/SKILL.md) 是本契约的唯一技能消费者。其余技能不写交接文件。新交接文件统一位于插件项目命名空间 `.steward/` 的 `handoffs/` 子树；该子树仍与同一命名空间下可跟踪的正式控制面文件隔离。

## 可以外移的内容

只有“证据与上下文”里的背景材料：相关文件与符号、当前行为、错误或日志原文、长篇接口说明、规范来源的引文。

结果、范围、约束与授权、完成标准、正当阻塞项和最终交付留在 GOAL 里。七行 GOAL 正文始终是边界事实源；完整工程闭环会把已接受正文持久化到 `.steward/goal.txt` 并在恢复和主要阶段切换时重新校验。交接文件只在被读取的那一次进入上下文，上下文一压缩就没了。把判定何时停、何时算完成的依据放进会被压掉的那一半，等于没有边界。

## 落点

落点固定在项目根下的 `.steward/handoffs/<安全标识>.md`，`<安全标识>` 由“结果”字段派生，只含小写字母、数字和连字符。用户在本次请求里点名确切项目相对路径时，只有规范化后的前两段精确为 `.steward/handoffs` 才使用；其他路径即使已被 git 忽略也不使用，只请用户改为 `.steward/handoffs/` 下的路径。

按顺序跑完下面这几项只读检查来定落点。任一项不通过就不写文件、也不在 GOAL 里写引用句：

| 检查 | 做法 | 判据 |
| --- | --- | --- |
| 解析项目根 | `git rev-parse --show-toplevel` | 退出码 0，且输出的 checkout 就是“证据与上下文”里已核实的那个项目 |
| 限定交接目录 | 规范化项目相对路径后比较前两段 | 前两段必须精确为 `.steward/handoffs`，且规范化结果仍在该子树内 |
| 确认未被跟踪 | `git ls-files --error-unmatch -- <路径>` | 退出码 1（未跟踪）通过。0 表示该路径已在版本控制里，128 表示落在项目外——`../` 与项目外的绝对路径都在这里被挡住 |
| 不覆盖既有文件 | 目标文件已存在时改用 `-2`、`-3` 递增后缀，取第一个不存在的路径 | 既有文件不读取、不比对、不删除，它可能是上一轮起草或别人的在途内容 |
| 确认已被忽略 | `git check-ignore -q -- <最终路径>` | 退出码 0 通过。1 时记下写入阶段要在 `.steward/handoffs/` 内补一条忽略规则。128（无法判定）按不通过处理 |

落点已被忽略是硬要求，不是偏好。[`run-closed-loop-verification`](../skills/run-closed-loop-verification/SKILL.md) 的 Git source provider 用 `git ls-files --cached --others --exclude-standard` 建 source inventory：已跟踪条目和**未被忽略**的未跟踪条目都进 source fingerprint。一份未被忽略的交接文件因此会制造 source drift，让正在跑的 schema-4 campaign 把当前 attempt 保存为 `INVALIDATED`、转入 `BLOCKED` 并要求新建 campaign root；portable evidence 的导出与聚合还另外要求 `source.excludes` 之外的 Git worktree 干净。

交接文件和忽略规则都只写在 `.steward/handoffs/` 里；项目既有的 `.gitignore`、`.steward/.gitignore` 及同一插件命名空间下的其他文件都不动。

## 顺序

上面这几项检查全都是只读的。落点定下来之后，先在内存里完成外移、写好引用句，把候选文本交给共享验证器重新校验。校验通过之后才开始写盘，一次落完：

1. 记了要补忽略规则时，新建 `.steward/handoffs/.gitignore`，内容恰为一行 `*`，再重跑一次 `git check-ignore` 确认返回 0；仍非 0 就不写交接文件，报出这份刚建出来的 `.gitignore` 的确切路径。这一行同时忽略 `handoffs/` 内的全部文件和它自己，整棵临时子树因此不进 `git status --porcelain -uall`，也不进 source inventory；它的作用域只覆盖 `handoffs/`，同一项目里 `.steward/invariants.json`、验证配置和其他正式控制面路径照常可以 add 和提交。不得在 `.steward/` 根写入会忽略整个插件命名空间的规则。

   该路径上已经有文件时不覆盖、不追加、不删除，直接按落点检查不通过处理：它既然没能让 `check-ignore` 返回 0，说明这个目录已被别的规则或用途占着。本契约授权的是新建那两个文件，不是改写任何既有文件。
2. 写交接文件。

写盘全部排在校验之后，是为了让“校验仍不通过”这条失败路径上磁盘保持原样。反过来先写后校验的话，一旦仍然超限，项目里就留下一份没人引用的文件和一个 `git status` 看不见的目录，用户没有线索去清理。

写入在当前沙箱与审批策略内完成。沙箱只读、写入被拒或路径不可写时，按落点检查不通过处理：不写文件、不写引用句。不为这次写入扩大沙箱或审批策略。

写盘任一步失败时，正文里那句引用已经写进去了，指向的文件却不在盘上。先回滚本轮已新建且内容仍未变的交接文件和自忽略规则；不删除、截断或改写任何本轮之前就存在或已发生变化的内容。回滚不完整时报出实际错误和残留路径。然后把引用句从“证据与上下文”撤回、把外移的背景放回原处，重新交给验证器校验，再按 `draft-consensus-goal` 的规则分支。带着悬空引用交付比没有附件更糟——执行方会去找一份不存在的文件，而它读不到的原因看起来和“换了 worktree”一模一样。

## 引用句

引用句并入“证据与上下文”字段，与该字段其余内容用中文分号衔接——七个字段各占一个逻辑行，引用句不另起一行。路径写成裸的项目相对路径，例如：

```text
补充背景见 .steward/handoffs/retry-backoff.md；该路径已被 git 忽略，可删除 .steward/handoffs/ 子树但不得据此删除整个 .steward/，执行前先读取；读不到时按本字段其余来源自行核实，不推测其内容，并在最终交付中说明
```

读不到就自行核实而不是停下，是因为没有任何机制保证读得到：该文件被 git 忽略，独立 worktree、另一个 checkout 或另一台机器上都不存在，而并行工作恰恰推荐用独立 worktree。真正的边界始终在 GOAL 的七个字段里，交接文件读不到只该让执行多绕一段路。

## 文件内容

按来源分块，每块标明出处（项目相对路径、命令或文档名），让执行方能自己回到原处复核。篇幅以被移出的内容为准：不写导语、不复述 GOAL 已有的字段、不加小结。

它是运行时读进去的普通内容，不是合同。因此不写授权、停止或完成判定的措辞，也不写 `C*` 编号、验证 case ID、adapter 路径或 digest——文件要是能授权或能定义完成，就等于在 GOAL 之外开了第二套合同。已被取代或被用户否决的方案也不写，哪怕标成“历史取舍”，那会以中立背景的形式绕过“范围”里的排除项。关于本次对话、本技能或所用工具的元信息同样不写。
