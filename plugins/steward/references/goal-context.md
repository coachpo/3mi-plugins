# GOAL 上下文文件契约

每次起草 GOAL 都必须在交付前新建且只新建一份项目内上下文文件。
GOAL 长度、背景多少以及用户是否另行要求文件都不改变这一要求。七行
GOAL 始终自包含并独自定义结果、范围、授权、完成与停止边界；上下文文件
只保存已核实来源和辅助背景，不携带授权、digest 或完成判定。

本契约是 GOAL 上下文文件的唯一落点和写入契约。旧路径
`.steward/handoffs/` 不受支持；不得读取、迁移、写入或删除其中任何内容。

## 目标绑定

只消费 `goal-authoring.md` 已冻结的 `<target-worktree-root>` 与 canonical
`view`。所有检查和写入都使用该精确根作为显式 workdir，不从插件目录、
shell cwd 或同仓库 sibling worktree 重新选根。恢复或上下文丢失、出现实际
漂移证据，以及开始本契约的实际写入前，按作者契约重新校验同一目标路径、
Git 目录与 common directory 绑定；校验失败立即停止，不再写盘。该检查不
证明在完全相同路径重建的仓库仍是原仓库。

## 合格内容与边界

文件必须至少包含一项已核实来源或合格背景，例如当前用户请求、后来明确
接受的决定、相关项目相对文件与符号、当前行为、错误或日志、接口说明，或
规范来源。未经核实的线索、被否决或取代的决定、无来源推断以及起草过程
元信息都不写；排除这些内容后为空则阻塞交付，不创建空文件或虚构背景。

结果、范围、约束与授权、完成标准、正当阻塞项和最终交付留在 GOAL 中。
上下文文件不写 `C*`、验证 case ID、adapter 路径、digest，也不使用授权、
停止或完成判定措辞。执行方读不到上下文时，应按 GOAL 中保留的来源自行
核实并在最终交付说明，不能推测文件内容。

## 唯一落点

目标路径固定为
`<target-worktree-root>/.steward/goal-context/<安全标识>.md`。从 `结果` 字段
派生 `<安全标识>` 时，把 ASCII 字母转成小写，保留 ASCII 数字，以单个
连字符替换其余连续字符并去掉首尾连字符，再截取前 64 个字符并重新去掉
末尾连字符；结果为空时使用 `goal-context`。用户点名路径时，仅接受规范化
后前两段精确为 `.steward/goal-context` 的项目相对路径。

以冻结目标为显式 workdir，清除 `GIT_DIR`、`GIT_WORK_TREE` 及其他会改选
仓库的环境覆盖，并按下列顺序完成落点检查。除 `check-ignore` 返回 1 外，
任一失败都阻塞写入和 GOAL 交付：

| 检查 | 做法与判据 |
| --- | --- |
| 项目根 | `git -C "<target-worktree-root>" rev-parse --show-toplevel` 的唯一输出再经 `worktree_binding.py verify-root` 校验，必须精确等于冻结根 |
| 目录边界 | 规范化路径必须仍在 `.steward/goal-context/` 内；已有 `.steward` 与 `goal-context` 组件必须是真实目录，不能是符号链接或其他类型 |
| 未被跟踪 | `git -C "<target-worktree-root>" ls-files --error-unmatch -- <路径>` 必须返回 1；0 表示已跟踪，128 表示目标越界，均失败 |
| 不覆盖 | 目标已存在时依次尝试 `-2`、`-3` 等后缀并选择第一个不存在的路径；既有文件不读取、不比较、不改写 |
| 已被忽略 | `git -C "<target-worktree-root>" check-ignore -q -- <最终路径>` 返回 0 才通过；1 仅表示写入阶段可新建子树自忽略规则，其他返回码失败 |

## 校验后写入

落点确定后，先在内存中完成上下文内容和 GOAL 内的引用句，再把完整七行
候选交给共享 GOAL validator。只有候选校验通过并且冻结绑定在写前复验
成功，才按顺序写盘：

1. 新建缺少的 `.steward` 与 `.steward/goal-context` 目录组件，记录本轮
   创建项以供回滚；不得穿过符号链接或改变既有目录。
2. 若 `check-ignore` 曾返回 1，新建
   `.steward/goal-context/.gitignore`，内容恰为一行 `*`，再运行同一
   `check-ignore`；仍非 0 则不写上下文文件。若该 `.gitignore` 已存在，
   不覆盖、不追加，直接失败。忽略规则只覆盖 `goal-context/`，不能写到
   `.steward/` 根，也不能隐藏 sibling 控制文件。
3. 在最终未占用路径新建上下文文件。

沙箱只读、路径不可写或写入被拒时，不扩大沙箱或审批范围；按写入失败
处理并阻塞 GOAL 交付。不存在退回纯内联 GOAL 的成功分支。

## 失败回滚

任一步写入失败时，只回滚本轮新建且内容仍未变化的上下文文件和自忽略
规则，再由深到浅移除本轮新建且仍为空的目录。不得删除、截断或改写任何
先前存在或随后发生变化的内容。回滚不完整时报告实际错误与残留路径。
随后撤回候选 GOAL 的引用句，把外移背景恢复到内存，仅报告 blocker 和
最小下一步；不交付带悬空引用或缺少上下文文件的 GOAL。

## GOAL 引用与文件格式

引用句并入 `证据与上下文` 字段，不另起第八行。只写项目相对路径，例如：

```text
补充背景见 .steward/goal-context/retry-backoff.md；该路径已被 git 忽略且仅作辅助上下文，执行前先读取；读不到时按本字段其余来源自行核实，不推测其内容，并在最终交付中说明
```

文件按来源分块并标明出处，让执行方能回到原处复核。篇幅以实际来源和
外移内容为准；不写导语、不复制第二份合同、不加小结。
